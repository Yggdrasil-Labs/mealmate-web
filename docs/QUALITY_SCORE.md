# Quality Score

Last updated: 2026-04-25

本文件定义 MealMate Web 当前的质量观察维度。它不是自动评分系统，也不伪造尚未存在的趋势图或 CI 分数；它用于帮助人和 Agent 在完成前做一致的质量判断。

## 1. 当前质量维度

| 维度 | 当前检查方式 | 通过标准 |
| --- | --- | --- |
| 架构入口 | 阅读 `AGENTS.md`, `docs/index.md`, `ARCHITECTURE.md` | 能判断改动应落在哪一层 |
| 业务语义 | 对照 `docs/PRODUCT_SENSE.md` 与 `docs/design-docs/` | 页面、路由、字段和测试用语不偏离统一语言 |
| 组件协议 | 对照 `docs/components/` 与组件测试 | 字段、事件、插槽和运行时行为有文档或测试支撑 |
| 计划状态 | 对照 `docs/skills/project-workflow/SKILL.md`、`docs/active/` 与 `docs/archive/` | 活跃工作、已完成记录和技术债不混放 |
| 验证路径 | 查看本次运行命令和测试覆盖 | 风险匹配的 lint、type-check、单测或 E2E 已运行 |
| 注释可读性 | 人工检查新增或显著修改代码 | 关键流程、关键分支与重要约束有注释支撑，注释占比至少 25% |

## 2. 推荐评级

| 等级 | 含义 |
| --- | --- |
| A | 文档、测试和代码边界一致；后续 Agent 能独立接手 |
| B | 主要路径清晰；存在少量未自动化检查或低风险遗留项 |
| C | 功能可运行，但文档、测试或边界存在明显缺口 |
| D | 依赖口头约定或外部上下文，后续改动容易漂移 |

默认不要求每次改动都写分数；只有阶段性复盘、重要里程碑或质量专项才需要记录评级。

## 3. 当前质量检测要求

- 人工质量检测除确认功能、结构与验证路径外，还应显式检查关键注释比例
- 对新增或显著修改的代码，关键注释占比至少达到 25%
- 若未满足该要求，应视为质量欠缺，而不是仅作为可选优化项

## 4. 自动化候选项

优先考虑把以下重复检查机械化：

- 路由 schema 中 title、menu、tab 的一致性
- 组件文档与公开 props / emits 的同步
- `docs/active/` 中长期未更新的计划
- 新增页面是否有路由入口和至少一个测试断言
- 关键文档索引是否链接到真实文件

后续若需要机械化评分，应先在仓库中形成稳定检查项，再考虑自动化。
