# MealMate 业务与领域上下文

本文档用于沉淀 `mealmate-web` 所依赖的业务背景与统一语言，确保页面设计、路由命名、接口字段和文案表达围绕同一套业务模型演进。

## 1. 系统本质

MealMate 不是单纯的菜谱展示系统，而是一个围绕家庭饮食决策的家庭饮食规划与执行系统。

核心业务闭环如下：

1. 建立家庭成员画像与饮食约束
2. 管理菜品知识库与标签体系
3. 生成一周用餐计划
4. 生成采购清单与备菜计划
5. 记录实际饮食情况
6. 对比计划与实际，形成营养分析与下一轮优化

## 2. 核心业务能力


| 业务能力   | 输入                 | 输出          | 核心规则               |
| ------ | ------------------ | ----------- | ------------------ |
| 家庭画像管理 | 成员信息、口味偏好、忌口、权限    | 家庭饮食画像      | 成员维度差异化约束          |
| 菜品管理   | 菜名、食材、标签、适配人群、营养信息 | 标准化菜品库      | 标签化、可筛选、可扩展        |
| 周计划生成  | 家庭画像、菜品库、季节信息、历史记录 | 7 天三餐计划     | 不重样、减脂分布、宝宝适配、口味平衡 |
| 备菜与采购  | 周计划、配方、库存/保存规则     | 采购清单、备菜计划   | 按餐次聚合、按食材归并、可保存    |
| 拍照记录   | 照片、备注、用餐时间、关联计划    | 实际饮食记录      | 计划与实际可追踪           |
| 营养分析   | 计划数据、实际饮食、营养规则     | 分析报告、优化建议   | 宝宝营养、减脂达标、均衡性评估    |
| 提醒与推送  | 计划、时间配置、任务调度       | 周六备菜推送、采购提醒 | 固定时点、可关闭、可回溯       |


## 3. 业务阶段

- 配置阶段：维护家庭成员、口味、忌口、权限与菜品库。
- 规划阶段：生成一周计划、筛选菜品、手动调整与补充自定义食谱。
- 执行阶段：采购、备菜、做饭、拍照记录与备注补充。
- 复盘阶段：计划与实际对比、营养分析、历史复用与策略优化。

## 4. 领域划分

### 4.1 核心域

- 家庭画像域：管理家庭成员、口味偏好、忌口、角色权限与饮食约束。
- 菜品中心域：管理菜品、配料、标签、适配人群、营养信息与季节属性。
- 用餐计划域：生成周计划、校验重复、安排减脂餐与适配宝宝餐。

### 4.2 支撑域

- 备菜采购域：根据计划生成采购清单、备菜计划与保存方式说明。
- 饮食记录域：记录实际食谱照片、备注与计划关联。
- 营养分析域：对计划与实际数据进行营养评估并形成建议。
- 推荐引导域：提供季节推荐、应急食材推荐与亲子活动建议。
- 消息提醒域：承接备菜推送、采购提醒与计划提醒。

### 4.3 限界上下文

- `Family Context`：家庭成员、偏好、忌口、权限、画像配置
- `Recipe Context`：菜品、配方、标签、营养信息、分类
- `MealPlan Context`：周计划、餐次安排、生成规则、重复校验
- `Preparation Context`：采购清单、备菜计划、保存方式
- `Record Context`：照片记录、备注、计划关联、差异比对
- `Nutrition Context`：营养报告、达标校验、建议输出
- `Recommendation Context`：季节推荐、应急食材、野菜活动建议
- `Notification Context`：提醒配置、定时任务、消息投递

## 5. 前端需要统一使用的业务术语

- 家庭成员：系统中的饮食参与者，如妻子、丈夫、宝宝。
- 饮食画像：成员口味偏好、忌口、饮食目标、限制条件的集合。
- 菜品：可被计划、推荐、记录的标准业务对象。
- 餐次：早餐、午餐、晚餐。
- 周计划：覆盖 7 天三餐的结构化用餐安排。
- 减脂餐：满足低脂、低卡、高纤维规则的特定菜品安排。
- 宝宝适配：菜品满足软烂、少盐少糖、无辛辣等幼儿约束。
- 备菜计划：面向执行层的食材前置处理、保存和烹饪说明。
- 采购清单：需要外出购买的食材汇总，由周计划自动归并生成。统一使用 `ShoppingList`，不使用 `PurchaseList`。
- 实际饮食记录：用户真实食用情况的照片与备注记录。
- 营养分析：对饮食结构进行规则化评估的结果。
- 提醒任务：系统内需执行的定时或触发式消息提醒任务。统一使用 `NotifyTask`，不使用 `Reminder` 或泛化的 `Task`。

## 6. 对 Web 仓库的直接影响

- 页面命名、菜单标题、页签标题与接口文案应围绕同一套业务术语表达。
- 页面编排应围绕“配置、规划、执行、复盘”业务阶段组织，而不是按技术模块随意切页。
- 表单、表格、详情组件中出现的领域字段应保持统一，例如 `ShoppingList`、`NotifyTask`、宝宝适配、减脂餐等。
- 后续新增页面时，应先确认其属于哪个业务阶段、服务哪个限界上下文，再进入路由和组件设计。
