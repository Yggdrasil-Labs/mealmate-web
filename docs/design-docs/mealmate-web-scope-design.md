# MealMate Web Scope Design

本设计文档聚焦 `mealmate-web` 仓库本身，说明 Web 端在整体 MealMate 系统中的职责、页面范围与实现边界。

## 1. 仓库职责

`mealmate-web` 是 MealMate 的 Web 前端仓库，负责承接家庭饮食规划与执行场景中的页面呈现、交互编排与壳层能力，不负责替代后端承载领域规则与数据持久化。

在整体系统中，Web 仓库重点负责：

- 承载首页、周计划、菜品库、备菜计划、饮食记录、营养分析、个人中心等页面
- 组织菜单、页签、缓存与布局等壳层体验
- 面向家庭饮食场景提供清晰的输入、浏览、调整与复盘交互
- 通过稳定接口契约与后端协作，而不是在页面中硬编码领域规则

## 2. 页面范围

Web 端的目标页面范围包括：

- 首页
- 一周计划页
- 菜品库页
- 拍照记录页
- 备菜计划页
- 饮食记录页
- 营养分析页
- 个人中心页

主链路围绕以下关键动作设计：

1. 查看并生成一周计划
2. 调整餐次菜品或手动补充菜名
3. 查看采购清单与备菜计划
4. 上传或补录实际饮食记录
5. 查看计划与实际的对比及营养分析

## 3. Web 端边界

### 3.1 当前适合在 Web 承载的能力

- 菜品筛选、浏览、录入与手动调整
- 周计划查看、替换、补充与状态展示
- 采购清单与备菜计划浏览
- 饮食记录的图片上传、备注补充与关联展示
- 营养分析结果呈现与历史复盘

### 3.2 明确不属于 Web 首阶段的能力

- 闪光灯控制、自动对焦等原生相机能力
- 依赖原生端体验的高级拍摄控制
- 直接在前端实现 AI 规则判断并绕过后端领域校验

### 3.3 拍照功能边界

Web 阶段拍照能力建议控制在以下范围：

- 支持通过文件选择或调用移动端摄像头上传图片
- 支持前端裁剪、旋转、缩放等轻量图片处理
- 上传后保存图片地址与裁剪信息，供饮食记录关联展示

不应在当前 Web 实现中承诺以下能力：

- 闪光灯调节
- 自动对焦参数控制
- 完整的原生拍摄体验

## 4. 与当前仓库实现的对照

当前仓库已具备以下基础能力：

- 基于 schema 的路由声明与标准化流程
- `DefaultLayout` / `BlankLayout` 壳层承载
- 菜单、Tabs、KeepAlive、响应式壳层状态管理
- 一组可复用的表单、表格、详情、搜索与对话框组件协议

当前仓库尚处于业务页面起步阶段：

- 路由中当前仅保留首页入口
- 首页仍是基础占位页，尚未落地 MealMate 的正式业务模块
- 业务设计文档已补齐，但页面、接口与数据流仍需按业务阶段逐步实现
