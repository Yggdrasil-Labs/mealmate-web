# Reliability

Last updated: 2026-04-25

本文件说明 MealMate Web 当前如何理解可靠性。作为前端仓库，它重点关注页面可用性、状态一致性、构建与测试可重复性，而不是声明尚未建立的线上 SLO、告警或值班流程。

## 1. 当前可靠性基础

- ESLint 保障基础代码规范
- `vue-tsc` 保障类型检查
- Vitest 覆盖单元与协议级验证
- Playwright 提供关键页面流程的端到端验证骨架
- 路由 schema、normalizer 和 shell 测试保障菜单、Tabs、KeepAlive 等壳层协议

## 2. 前端可靠性红线

- 路由、菜单、页签和页面标题不能各自维护不同事实。
- 页面加载、空状态、错误状态和重试路径不能只在理想数据下可用。
- 移动端视口不能因为固定宽度、悬浮交互或溢出文本破坏核心流程。
- 通用组件协议变化必须有文档和测试支撑。
- 构建、lint、type-check 或关键测试失败时，不应宣称改动完成。

## 3. 发布前验证分层

| 改动范围 | 最小验证 |
| --- | --- |
| 文档或注释 | 读取受影响入口，确认链接和事实来源一致 |
| 纯样式或小组件 | `pnpm lint`, 相关组件单测或手动视口检查 |
| 路由、shell、store | `pnpm lint`, `pnpm type-check`, 相关 router / store 单测 |
| 页面功能 | `pnpm lint`, `pnpm type-check`, 相关 Vitest，必要时 Playwright |
| 跨模块重构 | `pnpm lint`, `pnpm type-check`, 相关单测和至少一个关键 E2E 场景 |

## 4. 当前仍在建设中的部分

- 更完整的业务流程回归
- 更系统的页面状态与异常路径验证
- 更清晰的发布前验证分层
- 面向真实接口失败、慢请求和部分数据缺失的测试样例

## 5. 本文件的职责

记录稳定性目标、已知风险和后续可靠性工作方向，不在这里伪造尚未存在的 SLA、SLO 或告警体系。
