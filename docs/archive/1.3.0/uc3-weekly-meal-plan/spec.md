# 产品规格：UC3 生成周计划（前端）

## 问题与动机

后端提供周计划生成、调整和确认的 API 后，前端需要新增"周计划"页面，以 7×3 网格视图承载计划展示与交互操作。用户通过此页面触发生成、浏览计划、替换/添加/删除菜品、确认计划。

## 功能边界

**做什么（In Scope）**：
- 新增路由 `/weekly-meal-plan`，注册到 route schema
- 7×3 网格布局展示周计划（行=天，列=餐次；或行=餐次，列=天）
- 周选择器（默认当前周，可切换）
- "生成计划"按钮触发后端 API
- 单餐次菜品的替换、添加、删除操作
- "确认计划"按钮
- 不同状态（DRAFT/CONFIRMED/ARCHIVED）的 UI 差异化展示
- 新增 `src/modules/meal-plan/` 业务模块

**不做什么（Out of Scope）**：
- 拖拽排序菜品
- 计划对比视图
- 打印/导出功能

## 用户场景

### 场景 1：查看与生成

1. 用户导航到"周计划"菜单
2. 页面展示当前周计划（若无则显示空态引导）
3. 用户选择目标周，点击"生成计划"
4. 加载态后展示生成的 7×3 网格

### 场景 2：调整菜品

1. 用户点击某格中的菜品卡片
2. 弹出操作面板：替换 / 删除
3. 替换时弹出菜品选择器（带搜索过滤）
4. 添加时在餐次末尾打开菜品选择器

### 场景 3：确认计划

1. 用户点击"确认计划"按钮
2. 二次确认对话框
3. 确认后网格变为只读态

## 验收标准

- [ ] 周计划页面可通过菜单导航访问
- [ ] 生成后正确展示 7×3 网格，每格显示菜品名称列表
- [ ] DRAFT 状态下可替换、添加、删除菜品
- [ ] CONFIRMED 状态下操作按钮隐藏或禁用
- [ ] 确认后可跳转备菜计划页面，显示食材任务列表
- [ ] 确认后可跳转采购清单页面，显示合并后的食材采购项
- [ ] 备菜任务可标记为已完成，采购项可标记为已采购
- [ ] 移动端视口下网格可纵向滚动查看

## 产品约束

- 页面标题使用"周计划"，统一术语 `WeeklyMealPlan`
- 遵循现有 route schema + shell 协议
- 新模块放置在 `src/modules/meal-plan/`
- 状态管理复用 Pinia 模式
