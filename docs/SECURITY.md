# Security

Last updated: 2026-04-25

本文件记录 MealMate Web 前端仓库的安全边界与维护注意事项。它不替代后端认证、授权或审计设计，但要求前端不要削弱这些边界。

## 1. 当前边界

- 本仓库是 Web 前端，不在前端硬编码后端领域规则或敏感校验逻辑
- 接口通信优先通过统一请求封装处理
- 敏感配置不应直接写入仓库文档或源码常量

## 2. 当前最重要的约束

- 不在页面模板或通用组件中散落请求细节
- 不在前端承诺超出当前实现的权限与安全能力
- 不将外部凭证、密钥或敏感测试数据写入仓库
- 不把本地调试 token、真实家庭数据、真实图片或第三方账号信息写入 fixture、截图或文档
- 用户可输入内容进入组件展示、搜索、筛选或接口参数前，应经过类型约束、表单校验或请求层规范化

## 3. 前端实现要求

- API 请求优先收口到 `src/utils/api/`、composable 或 store，不在页面中复制请求协议。
- 表单和路由参数通过 TypeScript 类型、Vue props、Element Plus 表单规则或专门的解析函数约束。
- 错误提示面向用户可理解，不暴露 token、完整请求体、堆栈或内部接口细节。
- 权限相关 UI 只能作为体验优化，不能被描述为真正的授权边界。
- 文档示例使用脱敏数据，避免把真实个人信息固化为测试样例。

## 4. 本阶段范围

本文件当前记录前端侧安全约束，不声明尚未建立的审计、扫描或响应流程。需要引入依赖扫描、密钥扫描或安全 CI 时，应先形成执行计划，再把稳定规则写回本页。
